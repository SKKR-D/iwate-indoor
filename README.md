# 県インドア大会システム（iwate-indoor）

第40回岩手県中学校インドアソフトテニス大会の申込〜当日運営システム。
構成：GitHub Pages（画面）＋ Google Apps Script（処理）＋ Googleスプレッドシート（データ）。
既存の連盟システム（moeagare-iwate）とは独立しており、加盟チーム名簿だけを登録システムから読み取り専用で取り込む。

## 初回デプロイ手順

### 1. スプレッドシートとGAS

1. Googleドライブで新しいスプレッドシートを作る（名前例：`県インドア2026_DB`）
2. 「拡張機能」→「Apps Script」を開く
3. `Code.gs` の中身を `gas/Code.gs` で全文置き換える
4. 「プロジェクトの設定」→「"appsscript.json" マニフェスト ファイルをエディタで表示する」にチェック → `appsscript.json` を `gas/appsscript.json` で置き換える
5. 関数 `setup` を選んで「実行」→ 権限を承認する
   → シート「設定」「加盟チーム」「出場枠」「個人ペア」「ログ」ができる
6. シート「設定」を確認・修正する（特に **管理パスワード**、**サイトURL**、申込開始・締切）
7. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 実行ユーザー：自分
   - アクセスできるユーザー：全員
8. 表示された **ウェブアプリURL**（`https://script.google.com/macros/s/.../exec`）をコピー

### 2. 画面ファイル

1. 次の5ファイルの先頭付近 `var GAS_URL = 'PASTE_GAS_URL_HERE';` を、手順1-8のURLに書き換える
   - `index.html` / `entry-team.html` / `entry-individual.html` / `ticket.html` / `admin.html`
2. GitHubの `iwate-indoor` リポジトリに push
3. リポジトリの Settings → Pages → Branch：`main` / `(root)` で公開
4. 公開URL（`https://skkr-d.github.io/iwate-indoor/`）がシート「設定」の **サイトURL** と一致しているか確認

### 3. 連盟HP（moeagare-iwate）

大会要項・参加申込の申込先を `https://skkr-d.github.io/iwate-indoor/` に向ける。

## 運用の流れ（申込系）

1. `admin.html` →「加盟チーム名簿」→「名簿を更新」（登録システムから取り込み）
2. 「団体戦 出場指定」で男女各16チームにチェック → 保存
3. 「個人戦 ペア登録」で男女各16ペアを登録（合同ペアは支払チームを指定）
4. 確定名簿PDF（`01_個人戦出場ペア名簿.pdf`・`02_団体戦出場チーム一覧.pdf`）を、GASを動かしているアカウントのGoogleドライブに置く（ファイル名は完全一致。設定シート「個人戦名簿PDF」「団体戦名簿PDF」でファイル名・ID・URLに変更可）。リンクメールは区分に応じて件名が変わり、該当する名簿が添付される。見つからないと1通も送信しない
4-1. 設定シートの「申込開始」を確認してから（メール本文の申込期間はこの値）、11/1夜に「申込状況・リンク」→「未送信のチームにリンクを送信」。申込開始は11/4 9:00。それまでリンクは開けるが送信はできない
4-2. 11/2〜11/3に「未開封」のチームを確認し、届いていないチームへ連絡
5. 申込期間中は「申込状況・リンク」で状況を確認。⚠要確認（名簿外の選手）は個別に確認
6. 「未開封」のチームや、届かないと連絡のあったチームには、管理画面から再送するか、リンクのコピーボタンで個別に連絡
7. 締切前に「未申込のチームに督促メール」で督促

## 仕様メモ

- 申込時の選手変更（競技委員会承認）：管理画面「個人戦 ペア登録」の「申込時変更」で、ペアの変わる選手（A/B）と理由を設定 → そのペアの申込フォームに代わりの選手を選ぶ欄が出る（必須）→ 申込の送信で選手変更として記録（1ペア1名の枠を使う。締切までは選び直し可）。「理由を選手変更一覧に載せる」にすると、公開の選手変更一覧・プログラムに理由が出る（個人ペアシート「申込時変更」列・選手変更シート「理由公開」列は自動で追加）

- 地区：団体登録の「01_久慈」のような番号つきの地区名は、番号を外して表示（名簿の取り込み時にも外す）。並びは中体連の地区順（DISTRICT_ORDER）

- プレビュー（非公開）：管理画面「組合せ」タブの「👁 プレビュー」から、保存済みの組合せ案で組合せ表・進行表・プログラムを表示（`?preview=1`、POST adminPreview / adminPreviewProgram。管理パスワードか組合せパスワード）。シートには書かない。公開の進行表・プログラムは、進行表を作成した区分だけ組合せ（ブロック・組合せ番号）を返す

- 同じ名前で男女別に団体登録しているチーム（例：OWLS ONE）は、区分の性別に合う種別の登録（男子／女子、なければ男女）を使う：出場枠の代表者、申込フォーム・変更申請・ペア登録の選手候補。過去に作った枠の代表者は関数 fixEntryReps を1回実行して合わせ直す（未申込の枠だけ。直した枠はリンク未送信に戻る）

- 個人戦ペアの表示はフルネーム（氏名の空白を除いて統一：例「佐藤翔・中村陽」）。組合せ入力の選択肢は学年の丸数字つき（「佐藤翔①・中村陽②（さくら中）」）。組合せ表・プログラムは姓名を分けて学年の丸数字つき

- 選手・監督の変更申請：申込締切後〜大会当日の受付終了（設定「個人戦日程」「団体戦日程」と「受付時刻」の終わり＝8:00）まで。監督が change.html で申請 → 「変更申請」シートに記録 → 管理画面「選手変更」で許可（既存の変更関数で反映・選手変更シートに記録）／却下（理由必須）→ 申込責任者へ結果メール。設定「変更申請の通知先」にメールアドレスを入れると申請時に通知。本部画面に申請件数を表示。団体戦の選手交代は、終わっていない試合の提出済みオーダーの名前も置き換える（欠員の場合は本部に訂正を促す）
- 監督（ベンチ入り指導者）の氏名は、申込フォームの同意文（選手本人・保護者・監督の同意）の範囲で公開する（プログラムのチーム名簿・ペア一覧、選手変更一覧）。役職・連絡先と申込責任者の情報は公開しない
- プログラム：役員は「プログラム_役員」シート（区分・役職・氏名・所属）、栄光の記録は「プログラム_栄光の記録」シート（回・年度・種別・優勝・準優勝・3位・3位（2））に入れると表示。空なら「後日掲載」

- 組合せ係：設定シート「組合せパスワード」（初期値は空＝無効）でadmin.htmlにログインすると「組合せ」タブだけが出る。できるのは組合せの閲覧と「組合せを保存」まで。進行表の作成（＝公開）・個人情報・メール・本部画面は不可。進行表作成後の区分は変更不可。保存はログに「（組合せ係）」と残る

- 審判の割当（Progress.gs `refereeMap_`）。本部画面・進行表のカードに「審判：」、団体戦の監督ポータルに「審判の担当」を表示
  - 個人戦：予選リーグはリーグ内（`LEAGUE_REFS`：1-2→3番、3-4→1番、1-3→4番、2-4→1番、2-3→4番、1-4→2番）。決勝T1回戦は各コートの初戦をA・Bブロック3位、2戦目は同じコートの初戦の敗者。準決勝・決勝は審判員
  - 団体戦：試合順はAコート＝1-2、3-4、5-6、7-8、1〜4、5〜8、準決勝／Bコート＝9-10、11-12、13-14、15-16、9〜12、13〜16、準決勝。決勝は2面展開。各コートの初戦はAコート＝組合せ7番・8番、Bコート＝15番・16番のチームから1名ずつ。2戦目以降は同じコートの直前の試合の敗者。決勝は審判員
  - 予選順位の入力は1〜3位を選ぶ（A・Bブロックの3位は審判に使う。「予選順位」シートに「3位」列。初回保存時に自動追加）。組合せ表の順位は本部の確定値。3位が未確定のときは、残り2ペアの勝数が違うか2ペアだけの同率（直接対決）のときだけ自動表示し、3ペア以上の同率が絡むときは空欄
  - 予選リーグ表の「得失」欄は本部が表示を選んだブロックだけ公開（進行表・組合せ表）。本部の「得失の欄」で種類（個人戦：得失ゲーム／得失ポイント、団体戦のリーグがある場合は得失マッチも）と組ごとの値を入力。空欄の組は出ない。「予選順位」シートの「得失表示」「得失値（JSON）」列（初回保存時に自動追加）。本部画面のG差は参考表示（公開しない）
- 予選リーグの試合順：各コートで2つのブロックを1試合ずつ交互（A1-2 → B1-2 → A3-4 → B3-4 …）。審判をしたペアの試合は、早くても1試合あとになる
- 運営体制：各会場9人（本部2・受付2・記録掲示1・審判員4）

- 申込フォーム（団体・個人）に「個人情報の取扱い」への同意チェックあり（選手本人・保護者・監督の同意）。未チェックでは送信不可（GAS側でも確認）。同意日時は出場枠シートの「公開同意日時」列に記録（列は初回保存時に自動追加）

- 申込リンクは「区分×チーム」ごとに1本（推測できない16桁トークン）。同じチームの複数区分は1通のメールにまとめて送る
- 申込済みのリンクを開くと修正画面になる。締切後は閲覧のみ
- 申込時に「組合せ表記（略称）」を入力（必須・6文字以内。初期値は「○○中学校」→「○○中」）。文字数の上限は「設定」の略称最大文字数で変更可
- 申込書PDF（A4縦1枚）：確認メールに添付。申込画面・管理画面からもダウンロード可。Googleドキュメントで一時作成→PDF化→一時ファイルはゴミ箱へ
- 管理画面「申込一覧・PDF」：区分ごとの一覧表示・印刷（A4横）、区分別の一覧PDF（4区分）、各チームの申込書PDF。並びは中体連の地区順
- 確認メール・受付票に開場／受付時刻を表示（「設定」の開場時刻・受付時刻）
- 受付票の二次元コードの中身は `IWIN:受付コード`（申込リンクのトークンとは別の値）
- 団体戦：選手1〜8、最低4名（5〜8番は欠員可）、登録名簿から選択（選択済みはグレー表示）。名簿外の選手は手入力でき、管理画面で「要確認」表示
- 個人戦：ペアは連盟が事前登録。申込者はペアごとの監督と申込責任者を入力。参加料は支払チームにまとめて計上
- メール送信はすべて管理画面からのみ（HPに再送ボタンは置かない：第三者による迷惑メール・送信枠の消費を防ぐため）
- 申込リンクを初めて開いた日時を記録し、管理画面で「未開封」を表示
- 全セル「書式なしテキスト」で保存（日付・スコアの自動変換防止）
- コード規約：ES5（var / function のみ）

- 領収書：A5横。宛名はチーム名（個人戦の合同ペアは相手チームも併記）。発行者・代表者・角印は設定シートで指定
- 領収書PDFは申込締切後〜大会前日に管理画面「領収書PDFを事前作成」で作っておく（Driveの「県インドア大会_領収書」フォルダに保存）。受付時はそれを添付するので速い
- 紙の領収書：管理画面「申込一覧・PDF」→「領収書（印刷用）」（A5横・1チーム1ページ。A4に2ページ/枚で印刷）

## 選手変更

- 管理画面「選手変更」タブ（本部入力）。紙の選手変更届を受け取ってから入力
- 団体戦：番号（1〜8）を選び、登録名簿の選手（または手入力・要確認）に差し替え／「欠員にする」。6名未満は第3マッチ欠員（不戦敗）の表示
- 個人戦：ペアの選手A・Bのどちらか1名のみ。交代は抜ける選手と同じチームから。元の選手に戻すと「変更なし」に戻る
- すべての変更はシート「選手変更」に履歴が残る。申込書PDFの備考に「選手変更（変更前：○○）」と表示

## 組合せ・進行表（フェーズ3）

- 管理画面「組合せ・進行表」タブ：枠ごとに選択、またはExcelの組合せ表を貼り付けて「取り込む」→「保存して進行表を作成」
- 団体戦：枠1〜16（1回戦は1-2、3-4…）。既定のコート割り：1回戦第1〜4試合＝A、第5〜8試合＝B、決勝は2面展開
- 個人戦：A〜Dブロック×4。リーグ順は1-2、3-4、1-3、2-4、2-3、1-4。A・BブロックはAコート、C・DブロックはBコート。決勝T：A1-C2、D2-B1、C1-A2、B2-D1
- 予定時刻：競技開始9:00、5ゲーム20分、7ゲーム30分。団体戦1試合＝1面は5G×3、2面展開は5G×2。団体戦は前の試合の終了から15分（オーダー提出・集合）を空ける。試合が始まると、遅れは現在時刻から再計算
- 本部（control.html）：コール→開始→結果入力（勝者＋スコア）。勝者は自動で次の試合へ。▲▼で順番入替、⇄でコート移動、2面展開の切替、予選順位の確定、目安時間の変更
- 公開（progress.html）：URLを掲示・QRで配布。区分の切替タブあり

## 団体戦の運営（フェーズ4）

- 監督：受付票の「オーダー提出（監督用）」→ 選手名を選んで提出（選択済みはグレー、6名未満は第3マッチが欠員（不戦敗））
- オーダーの公開：両チームそろうと本部画面に「未公開」→ 試合開始のあいさつで本部が「📣 オーダー公開」。公開までは相手・観客に見えない。監督が自分で修正できるのはオーダー提出の締切まで（1回戦は設定の時刻、2回戦以降は前の試合の終了＋設定の分）。締切後・公開後の変更は本部のみ（締切後の初回提出は可、警告表示）。押し忘れても「開始」で自動公開。試合開始前なら「非公開に戻す」可
- 締切：1回戦は設定「1回戦オーダー締切」（初期8:40）、2回戦以降は前の試合の終了＋10分（集合は＋15分）。超過は本部画面に赤表示
- 本部：未提出チームは紙のオーダー票を受けて「オーダー」から代理入力（そろった後の訂正も可）
- 結果：本部が「マッチ結果」でマッチごとに勝者とゲーム数（画面の呼び方は「第1マッチ〜第3マッチ」。シートの列名は「番手」のまま）。1回戦は第3マッチまで、2回戦以降は2勝で決着（残りは打ち切り）。同数は 得失ゲーム差（自動）→ 得失ポイント差（本部入力）→ 代表戦（本部入力）
- 公開進行表：本部が公開した試合（または開始した試合）だけ、マッチごとの選手名と結果を表示
- スコアシート：本部のパスワードでログインした端末から開くと、公開前でも提出済みのオーダーを印字

## 監督へのお知らせ（団体戦のオーダーだけ・画面を開いている間）

- `coach-alert.js`。団体戦の監督ポータルだけで動く（個人戦の受付票には出さない）
- 出すのは2つだけ：①次の相手とオーダー締切が決まった（未提出）②締切5分前（未提出）。試合・審判のコール、表彰は会場の放送で知らせる（スマホをつけっぱなしにする必要はない）
- 画面いっぱいに出て「確認しました」を押すまで残る。確認したものはその端末に覚えて二度出さない
- 音は「🔔 音も鳴らす」を選んだ端末だけ、出たときに1回（マナーモードでは鳴らないことがある。振動・画面消灯の防止・通知は使わない）
- 本部（control）：団体戦で決着すると「📢 放送文」（結果と次の試合のオーダー締切）を出す。カードの「📢 放送文」でもう一度出せる

## 選手変更一覧を見られる人（個人情報保護）

- 一般には公開しない。トップページ・進行表のリンクは、見られる人にだけ出す
- 見られる人（GAS `changesAccess_`）：係員＝管理・受付・本部・組合せのパスワード（POST `changesList` の pw）／監督＝受付票の記号 t（受付票・監督ポータルのリンク、または端末の「戻る」情報）／会場の人＝合言葉 k（設定「限定公開の開始」〜「限定公開の終了」の間だけ）
- 合言葉：設定「会場の合言葉」。空欄なら一度だけ自動で作ってスクリプトのプロパティ（VENUE_KEY）に覚える。運営ポータルの「進行表の二次元コード」で係員のパスワードを入れると、合言葉入りの二次元コード（progress.html?div=..&k=..）になる（POST `venueKey`）
- 進行表・選手変更一覧は、受け取った k を端末に覚える（`iwateIndoorVenueKey`）。係員のパスワードは `iwateIndoorStaffPw`（本部・受付で入れたものも使う）
- プログラム（programData）の選手変更一覧も、見られる人のときだけ中身を入れる（`changesLocked`）

## コート集合・オーダー締切

- コート集合（GAS `gatherOf_`）：各コートの1試合目は設定「1試合目のコート集合」（9:00）
  - 団体戦の2試合目以降：同じコートの前の試合の決着と、勝ち上がってくる試合の決着（2回戦以降）の遅い方＋「コート集合（分）」（15）。決着前は「前の試合の決着から15分後」と表示
  - 個人戦の2試合目以降：「前の試合が終わり次第」。決勝トーナメントで各コート最初の試合は「本部のコールで」
- オーダー締切（`orderDeadline_` → `autoDeadline_`）：1回戦は設定「1回戦オーダー締切」、2回戦以降は勝ち上がりの決着＋「オーダー提出（分）」
- 本部の手入力：カードの「⏱ 集合・締切」（個人戦は「⏱ 集合」）→ 試合シートの「集合指定」「締切指定」（空欄＝自動）。ctlUpdate の op `times`。手入力の締切はオーダー修正の締切にも使う
- 表示：監督ポータル（コート集合）、本部カード（「手入力」の印）、進行表（これからの試合に「コート集合：…」）

## 変更申請の状況・選手変更一覧

- `coach-req.js`：受付票・監督ポータルの上に「📝 変更申請の状況」（⏳申請中／✅許可・反映済み／❌却下＋理由、却下で期間内なら「もう一度申請する」）。許可・却下に変わったら色付きの枠で目立たせ、「わかりました」を押すまで残す（端末に覚える）。GAS `myRequests_`（getTicket・portal の `requests`）
- 監督ポータル：申請中があると、オーダー画面に注意。次の試合の欄に相手チームの選手変更（GAS `oppChanges_`、`match.oppChanges`）
- 受付（reception）：一覧に「📝 変更申請中」（`recList` の `reqPending`）、チームを開くと申請の状況（`recLookup` の `requests`）
- 受付票・監督ポータルの下に「🔁 選手変更一覧を見る（区分）」
- 選手変更一覧（changes）：`?div=` は MI/WI/MT/WT（その区分）、I（個人戦の日＝男女）、T（団体戦の日＝男女）、all。指定なしは、きょうの種目（GAS `changesPeriods_` の `today`）。区分ごとに「受付中：8:00まで」／「🔒 受付終了 ― この一覧で確定」

## アクセス集中への備え（キャッシュ）

- 公開の進行表（`progress`）・監督ポータル（`portal`）・受付票（`getTicket`）・選手変更一覧（`changes`）の GET は、結果を CacheService に 8〜15秒ためて返す（`cachedJson_`）
- キーに「世代番号」（`cacheGen`）を含め、読むだけの POST（`POST_READONLY`）以外の POST があるたびに世代を更新（`bumpCacheGen_`）。結果入力・オーダー提出・受付などの直後は、ためた内容を使わずに作り直す
- スプレッドシートを手で直したときは、最大15秒ほど古い表示が残ることがある
- 95KB 以上の応答とエラー応答はためない

## 不戦勝・リタイアの表記と表彰の表示

- 不戦勝・リタイアのスコアは勝者から見て「4-R」（7ゲーム）、「3-R」（5ゲーム＝団体戦のマッチ）。R＝リタイアメント。保存は他のスコアと同じく左右の順（右の勝ちなら「R-4」）。本部の入力は「4-R（不戦勝・リタイア）」「3-R（不戦勝・リタイア）」ボタン、または「4-R」と入力。旧表記「不戦勝」も 4-R／3-R として表示。R のスコアは得失ゲームの計算に入れない
- 団体戦で選手6名未満のチームの第3マッチは「欠員（不戦敗）」。スコアは自動で「3-R」
- 表彰：団体戦は監督ポータル、個人戦（団体戦も）は受付票に、第3位（準決勝で負け）・準優勝・優勝が決まった時点で「🏅 表彰式があります。連絡があるまでお待ちください」を目立つ枠で表示（GAS `awardsFor_`、ポータルは `award`）。個人戦は「○○・○○ペア（第3位）と○○・○○ペア（優勝）は…」。受付票は30秒ごとに読み直す

## 監督の画面の行き来

- 受付票（ticket）・監督ポータル（portal）の「✏️ 選手・監督の変更申請」は、申請できる期間（申込締切後〜当日の受付終了）だけ表示（GAS が `changeOpen` を返す。古い GAS のままなら常に表示）
- 受付票：受付後は「📝 オーダー提出（団体戦）」「📋 進行表を見る」。受付済みは「✅ 受付済み（受付の時刻）」
- 監督ポータル下部（同じ大きさのボタン）：受付前は「🎫 受付票を表示する」、期間中は「変更申請」、いつでも「📋 進行表」「🏆 組合せ（結果入り）」「🔁 選手変更一覧」
- 変更申請のページ：下に「← 受付票に戻る」
- 「← 監督ポータルに戻る」（個人戦は「← 受付票に戻る」）：受付票か監督ポータルを開いた端末に戻り先を覚え（`coach-return.js`、ブラウザの保存。その日の終わりまで。URLには入れない）、進行表・組合せ・選手変更一覧（`<body data-coach-return="show">`）の画面下に固定で表示。運営の練習（practice/）では出さない
- 監督ポータルの試合カードに「次がこの試合です」「この試合の前に あと○試合（いま Aコートは第○試合が試合中）」（GAS `courtQueue_`。2面展開はA・B両方を数える）

## 操作練習（practice/）

- `practice/index.html` が入口。本番と同じページ（受付・本部・記録・管理・受付票・監督ポータルほか）の写しに練習エンジン（`engine.js`）を入れ、GAS のプログラム（`gas-src.js`）をブラウザの中で動かす。通信先（script.google.com）への送信はすべて端末の中で処理し、本番のデータには触れない
- 場面は4つ（個人戦の日・受付前／予選リーグの途中、団体戦の日・受付前／1回戦の途中）。架空の男女各16チームのデータ（`scenarios.js`）。練習の時刻は場面の時刻から実時間で進む（入口で変更可）
- データはその端末のブラウザの中だけ（同じブラウザのタブどうしで共有）。メールは送らず、入口の「送ったことになっているメール」に記録。PDFを作る機能は使えない
- パスワードは練習用（受付・本部・管理とも `renshu`）。ページが保存するパスワード等は練習用の名前で保存するので、本番の画面の保存と混ざらない
- 監督の操作体験：`practice/coach/`（入口 `index.html`）。架空の「さくら中学校」の監督として、団体戦（受付 → オーダー提出 → 試合 → 次のオーダー … → 敗退後の審判／優勝）と個人戦（受付 → 予選リーグの試合・審判の確認 → 決勝トーナメント）を体験。本部・相手チームの動きは「進める」ボタンで自動（結果の勝ち負けは選べる）。データは運営の練習とは別（`IWP_NS='coach'`、場面 coach-team／coach-indiv）。トップページの「監督向け 当日の動き（動画）」の枠（申込締切後に表示）からリンク
- 係ごとの練習カード：`practice/cards.html`（受付・本部・記録 × 個人戦・団体戦、印刷で1枚1ページ）
- 本番の GAS や画面を直したときは、練習版を作り直す（作成スクリプトは開発環境側）
